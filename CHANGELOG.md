# Changelog

## 1.3.0 — 2026-11-23

Shorten the workflow instructions and make project documentation proportional to the work.

- Keep the main skill focused on decisions and checkpoints. Put delivery, delegation, and documentation details in their respective references.
- Allow one combined project record or several files in both new and existing projects. Keep all five template roles available.
- Look up quick facts directly during workflow interviews. Use read-only delegation when it unblocks parallel questions or materially improves the result.
- Keep the existing model profiles, evidence-based escalation, test-first checks, isolated editing, and independent acceptance of user-facing outcomes.

## 1.2.1 — 2026-11-22

Outcome-focused validation and complete replacement/removal of existing behavior.

- Choose checks before implementation that reach the user-promised outcome, such as persisted data after reopening or a converted file working in its consuming application.
- Include a failure or conflict check when data loss or blocked work is possible. Examples guide selection rather than impose a fixed checklist; small edits need only focused checks.
- Reconcile affected active callers, tests, links, and instructions when replacing or removing functionality. Run changed documented commands exactly as documented or disclose the obstacle; retain historical material with a clear status label.
- Preserve model routing, workflow phases, document templates, and optional Git. No graph integration is added.
- Refresh Russian and English release descriptions, installation guidance, and an illustrative acceptance example. Package checks do not establish end-to-end application behavior.

## 1.2.0 — 2026-11-20

Model routing for routine and difficult development work.

- Recommend GPT-6.2 Sol High for the coordinator and keep the model selected for the chat.
- Use GPT-6 Luna Medium for narrow, independently checkable tasks and GPT-6.1 Terra Medium for routine implementation with clear requirements.
- Assign difficult work and substantive test design directly to GPT-6.2 Sol Medium when needed. The coordinator diagnoses failed checks before escalating and can allow one bounded correction for a local Terra defect.
- Pass existing changes and reproducible failures to the next worker. Keep the existing worker limit and test-first acceptance process.
- Update both READMEs, the installation guide, and the routing example.

## 1.1.0 — 2026-11-04

Documentation maintenance during ongoing development.

- Reuse existing project documents and update authoritative sections before creating new files.
- Keep detailed requirements in one place; use short status entries and links instead of duplicate contracts.
- Replace superseded wording, keep the active queue current, and retain unresolved issues and material evidence.
- Resume through current state and task-relevant sources; consult history only when needed.
- Give shared documents one owner and avoid permanent reports for every agent result.
- Preserve the initial five-document structure, all template sections, the interview, test-first implementation, model routing, and integration rules.
- Add the maintenance reference to package validation and document both current and previous release tags.

The v1.0.0 tag and release remain unchanged. Instruction scenarios were reviewed; token savings and long-running project behavior have not been measured.

## 1.0.0 — 2026-10-28

First public distribution of the existing AI Development Workflow skill.

- Includes the workflow entrypoint, model-routing and delivery references, UI metadata, and five project-document templates.
- Bundles the locally used Grilling and Domain Modeling snapshots with Matt Pocock's MIT notices.
- Adds Russian and English READMEs, installation guidance, illustrative prompts, contribution guidance, issue forms, and package validation on GitHub Actions.
- Removes a private pilot reference from the published routing introduction without making performance claims.
- Clarifies that fork options must match the runtime; removes an unsupported positive-number fork suggestion from the publication copy.

The installed local skills were not changed. This release adds distribution and documentation; it does not claim new end-to-end behavioral validation.
